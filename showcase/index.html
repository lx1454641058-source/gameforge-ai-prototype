GameForge AI

游戏项目评估、协作与上架准备原型

问题与产品责任

独立游戏创作者从方案、制作到协作和上架准备之间存在信息缺口。本人提出平台定位，拆分创作者、评审者、协作者与平台角色，负责用户流程、原型和 PRD，并借助 AI 推进独立评分模块。

关键路径

上传方案与 Demo → 生成问卷草稿 → 创作者确认 → 类型知识库比对 → 九维诊断 → 人工复核与行动建议。评分不是终点，还需解释缺失模块、能力需求和制作路线。

为什么这样设计

AI 可帮助理解资料，但不能覆盖创作者已确认事实；资料不足时应产生待补事项。结果要能追到输入、类型基线、规则版本和证据，便于用户复核。

GameForge：让结论可追溯

本人负责流程、规则边界、输入确认与成果核对

任务分解

① 整理 25 题版本化问卷，把类型、玩法、创新机制改为结构化回答。② 整理 28 类游戏知识和九维诊断结构，先比对类型基线再调整权重。③ 明确 AI 草稿、创作者事实和人工审核的权责。

异常与交付

推进上传格式、签名、大小和 ZIP 异常结构校验方案；Demo 不自动执行，资料按项目隔离。设计输入冻结、报告快照、重试和审计记录，避免结果覆盖后无法解释。

现有成果 / 当前取舍

公开仓库含平台界面和评分 Agent。已有问卷、知识库、流程和工程说明；完整平台后续开发因团队能力、周期和运营成本评估暂缓。规则仍需专家和真实项目校准，B_GATE 不等于真人审核通过。

面试演示建议

打开平台原型说明角色入口，再进入评分 Agent README 展示问卷和示例。解释一个关键答案未确认时应停止评分的例子。本轮未重新执行评分服务或全量测试。

展示与运行边界

在线交互原型。GitHub Pages 仅提供静态网页。Python/Node 后端、模型调用、硬件采集、真实交易与付款不由此网站运行；原型中的模拟数据不代表商业运营。
