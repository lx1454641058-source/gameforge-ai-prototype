## 结论

本次确认并修复 8 组缺陷。修复后 34 项自动化测试全部通过，Python 编译检查通过，每个 Python 非空代码行的 MIT SPDX 标注检查通过，GPL 许可证文本扫描通过。强样例仍稳定输出 `B_GATE`。

本版本可以作为本地参考实现继续开发，但还不能宣称已经完成正式游戏品质评分：Demo 目前只做 ZIP 静态安全检查，没有在隔离沙箱中启动或自动试玩；评分阈值仍是暂定规则，尚未经过领域专家与真实种子项目校准；可选模型代填未使用真实 API Key 做线上联调。

## 已修复缺陷

| 编号 | 级别 | 位置 | 修改前 | 修改后 |
|---|---|---|---|---|
| BUG-01 | 高 | `service.py`、`artifacts.py` | 客户端可以直接提交自制 `artifacts` 清单，也可把文本文件声明成 `demo_build`，从而伪造哈希、`ready` 状态或 Demo 类型。 | 提交必须使用上传接口签发的 `artifact_ids`；服务端重建清单；资料类型与扩展名绑定，`demo_build` 只接受 ZIP。 |
| BUG-02 | 高 | `intake.py` | 未登记问卷字段会进入项目对象，可能覆盖或注入内部字段；答案类型未校验。 | 只接受 19 个登记题号；按 text/list/object/boolean 等合同校验；阶段和商业模式使用明确枚举。 |
| BUG-03 | 高 | `intake.py` | 答案可引用不存在或不属于本次提交的资料；非创作者答案可以没有证据；未确认的可选 AI 答案仍可能影响诊断。 | 所有证据引用必须属于本次清单；非创作者非空答案必须有证据；只有创作者确认的答案进入评分对象。 |
| BUG-04 | 中 | `agent.py` | 五个空白字符串会被当成五步核心循环；空白角色或范围会提高可落地性分数。 | 只统计非空行为步骤、角色与范围；纯空白文本统一视为缺失。 |
| BUG-05 | 中 | `repository.py` | SQLite `IN` 查询未保证资料返回顺序；重复标识语义不明确，可能导致清单哈希不稳定。 | 按调用顺序重排可信记录；明确拒绝重复资料标识。 |
| BUG-06 | 高 | `repository.py`、`service.py` | 同一运行可能被重复领取；运行中、待创作者行动或不可重试失败也可被重试；终态写入没有状态条件；中断恢复缺少审计事件。 | 条件式原子更新；只允许 `queued` 或 `failed + retryable=true` 被领取；只有 `running` 可完成或失败；待补充必须创建新提交；恢复过程追加审计事件。 |
| BUG-07 | 中 | `capabilities.py`、`service.py` | 高等级但无考核证据的能力仍可推荐；负返工次数、缺审核人或错误 JSON 类型的履约反馈可能进入能力历史。 | 无证据或无考核版本的能力进入重新考核；履约字段执行类型、范围和必填校验，非法事件拒绝写入。 |
| BUG-08 | 中 | `api.py`、`artifacts.py` | Token 使用普通字符串比较；POST 未限制 JSON 媒体类型；未知运行审计返回伪 200；DOCX 恶意或损坏 XML 可能成为不透明错误。 | Token 改为恒定时间比较；强制 `application/json`；未知审计返回 404；拒绝 DTD/实体并把损坏 XML 映射为上传校验错误。 |

## 尚未完成的能力边界

1. Demo 只登记哈希、校验 ZIP 结构和压缩风险，不会执行游戏、录制玩法或验证“真的可玩”。
2. PDF、图片和视频目前不做正文、OCR 或多模态理解，只保存可信元数据和能力限制说明。
3. `GF-GAME-RUBRIC-0.1-PROVISIONAL` 仍是暂定评分阈值；在专家校准完成前，`B_GATE` 不能等同真人 BAS 分数或真人审核资格。
4. OpenAI 问卷代填路径没有在本机使用真实 API Key 联调，本次只验证了保守代填、结构合同和异常边界。
5. 上传层尚未接入独立杀毒引擎、内容净化服务或真正的 Demo 隔离运行沙箱。
